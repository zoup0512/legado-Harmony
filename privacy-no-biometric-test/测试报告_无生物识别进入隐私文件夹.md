## 1. 结论摘要

在无生物识别的模拟器上，隐私文件夹的"无生物识别"路径表现符合设计：

- **检测正确**：应用准确识别"设备未录入指纹或人脸"，全程**未弹出系统指纹/人脸认证弹窗**；
- **正确降级到 PIN**：未设置时引导设置六位密码；已设置时直接进入 PIN 验证页；
- **锁定/解锁行为正确**：离开应用自动上锁；Tab 内切换不上锁（符合"离开应用即自动上锁"的设计）；
- **防暴力破解有效**：连续失败触发指数冷却（第 5 次失败 → 30 秒冷却），冷却期提示带倒计时，冷却结束后可正常解锁；
- **取消路径安全**：PIN 验证页点"取消"回到锁定页，不泄露私密内容。

对照组（背景信息）：同一应用在真机（华为 nova 16 Ultra，已录入指纹）上进入隐私 Tab 会弹出系统"请验证指纹"弹窗（截图 `screenshots/02_privacy_tab_tapped.jpeg`），且锁定页按钮文案为"指纹 / 人脸解锁"；模拟器（无生物识别）下按钮文案为"输入密码解锁"。两种环境的 UI 分支与代码设计（`PrivacySessionService.unlock()`：生物识别可用→系统认证；不可用→PIN）一致。

## 3. 重要前置说明：ReaderKit 环境阻塞与测试专用桩

### 3.1 阻塞与处理

应用静态依赖华为 HMS **ReaderKit**（`@kit.ReaderKit`，运行时解析为系统应用 `com.huawei.hmsapp.readerkit` 的 kitview.hsp）。该 Kit 预装在华为真机上，但**所有 DevEco 模拟器镜像（5.1.1 / 6.1.1 / 7.0.0）均未随附**——镜像内只有 kit 映射配置，无实际 HSP（已通过镜像文件 grep + `bm dump` 双重确认）。应用在模拟器上启动即 SIGABRT 崩溃（崩溃日志摘录见 `crash_readerkit_hilog_excerpt.log`：`LoadJSPandaFile ... resolveBufferCallback get hsp buffer failed`）。

**处理方式**：在项目**副本**（`C:\Users\24790\AppData\Local\Temp\legado_emutest\harmony_Legado`，未触碰当前工作区）中新增本地桩模块 `entry/src/main/ets/readerkitshim/ReaderKitShim.ets`，按 SDK 类型声明提供同名同签名实现，并将 6 个文件的 `@kit.ReaderKit` 导入指向该桩后构建。

### 3.2 对测试有效性的影响

- **不受影响**：本次被测的隐私功能代码（PrivacySessionService / PrivacyCredentialService / PrivacyPinPolicy / PrivacyAuthPage / PrivacyPinPad / PrivacyFolderView 等）**未做任何修改**，其认证、PIN、锁定、冷却逻辑全部为原代码；
- **不覆盖**：阅读器页面与书籍封面解析（ReaderKit 相关功能）在模拟器上不可用，但该功能与本测试场景无关；
- 若后续需要在模拟器上测试阅读器功能，需真机配合或等待模拟器镜像提供该 Kit。

## 6. 观察与建议（非缺陷）

1. **真机上"取消指纹弹窗"无 PIN 降级入口**（对照组观察，非本次场景）：设备已录入指纹时，取消系统指纹弹窗后回到锁定页，只能重试指纹，无法用 PIN 进入。这与页面提示"未录入时使用六位密码"的产品设计一致，但存在一个边界场景：若用户系统指纹认证被临时锁定（多次指纹错误触发系统级锁定），将无法进入隐私文件夹。可评估是否需要在生物认证失败/锁定时提供 PIN 降级入口。
2. **弱 PIN 无限制**：PIN 策略允许任意 6 位数字（如 000000、123456）。防暴力破解由失败冷却兜底，可接受；如需更强安全可考虑拒绝弱 PIN。
3. **模拟器无生物识别是天然的"无生物识别"测试环境**：建议将该场景纳入回归（本次已完整覆盖）。

### 7.2 本次发现的环境要点（供后续测试参考）

- DevEco 模拟器启动方式：设备管理器（工具 → 设备管理器）点击 ▶；CLI `Emulator.exe -hvd <名称>` 会被华为账号校验拦截，需从 IDE 内启动。
